# SDM 材料库设计

> 材料是各类仿真计算模型的核心输入。本文记录材料库的定位、数据模型与已定决策。
> 一期范围：库本身 + 种子数据导入 + 管理页。零件→材料匹配仅做规划（见末节），不实现。
>
> **进度**：一期已实现——`sim_material*` 四表（sim/db.py）、关键字导入器
> （sim/materials/）、/sim/materials API（写仅管理员）、前端材料库页（含曲线族
> SVG 预览与卡原文查看），测试在 tests/test_sim_materials.py。

---

## 1. 定位

材料库是 **SDM 全局资产**，与 `sim_template`（工况模板）、质量卡模板库同级——
不属于某个项目，项目只是引用它。解决两个问题：

1. **归一**：产品数据里的材料写法不规范（"Q235"、"Q235-A"、供应商牌号混用），
   最终要能把零件上的原始材料文本匹配到唯一的库内材料（二期）；
2. **仿真可用**：材料不只是一个名字，要携带求解器需要的性能参数、曲线、
   乃至经过工程验证的现成材料卡（一期）。

### 两层模型：物理材料 vs 模型变体

种子文件里 `HC180BD+Z.1` 带模型变体后缀、`SAPH440_NULL` 是伴生 NULL 材料——
同一物理材料在求解器里有多个模型变体。库内显式分两层：

- `sim_material` —— 物理材料（牌号、分类、标准号），求解器无关；
- `sim_material_card` —— 该材料在某求解器下的某个模型变体
  （如 LS-DYNA 的 MAT24 主卡、伴生 NULL 卡）。

零件匹配、检索、统计都对物理材料层做；导出输入卡时才落到具体变体。

## 2. 数据模型

```
sim_material               物理材料主数据（牌号、分类、标准号、来源、修订）
├─ sim_material_property   标量性能：密度/E/泊松比/屈服…（带单位 + 适用条件）
├─ sim_material_curve      曲线：应力-应变、S-N…（族分组 + 适用条件 + 点列）
└─ sim_material_card       求解器卡：结构化参数 + 关键字原文块，按 solver_type
```

二期（规划，暂不建表）：

```
sim_material_alias         别名表：见过的原始写法 → 归一材料
sim_part_material          项目内实例：零件 × 匹配结果 × 材料修订号
```

### 关键设计

**原始卡片段原样保留（verbatim）。** 种子数据里的卡是经过工程验证的，重新生成有
出错风险。`sim_material_card` 同时存关键字原文块与解析出的结构化参数：导出时优先
用原文，结构化参数用于展示、检索和跨求解器映射。这与质量卡"派生文件本身就是合法
ANSA 卡，不做二次转换"是同一哲学。

**曲线支持"曲线族"。** 碰撞材料的应力-应变曲线按应变率分族——LS-DYNA 的
`*DEFINE_TABLE` 正是这个结构（如 SAPH370：应变率 0/0.1/1/10/100/1000 s⁻¹ 各挂
一条曲线）。`sim_material_curve` 用族分组字段 + `condition_json`（应变率、温度等）
表达，同族曲线共享 family key，导入时与 DEFINE_TABLE 一一映射。

**单位制按声明存，不强转 SI。** 碰撞行业惯用 t-mm-s（密度 7.85E-9 t/mm³、模量
MPa），强转 SI 再转回只会引入误差。数值按导入时的单位制存储并在卡上显式声明
`unit_system`，导出时如项目单位制不同才换算。

**修订版本化。** 材料数据有来源（手册/试验报告/供应商），试验数据更新出新修订；
将来 `sim_part_material` 记录的是"匹配到材料 X 的修订 N"，保证已算工况可复现——
与几何/网格版本化同一理由。

**标量性能层不是权威数据。** 密度、模量等在求解器卡里已有；`sim_material_property`
是物理材料层的展示与检索用途（列表筛选、对比），导出以卡为准。

## 3. 种子数据

`ref/06_Material_T_mm_12.k.key`（LS-DYNA keyword，t-mm-s，R11）：74 张材料卡
（57 张 `*MAT_PIECEWISE_LINEAR_PLASTICITY` 常用车身钢种 + 弹性/NULL/刚体/点焊/
蜂窝/夹层玻璃等），220 条 `*DEFINE_CURVE`，30 张 `*DEFINE_TABLE`。

一期实现 keyword 材料段导入器（`sim/deck` 已有 keyword 解析基础）：

- `*MAT_*_TITLE` → `sim_material_card`（原文 + 结构化参数），并按标题归一出
  `sim_material`（剥离 `.1` / `_NULL` 等变体后缀，变体关系落在卡层）；
- `*DEFINE_TABLE` + 其下 `*DEFINE_CURVE` → 一族 `sim_material_curve`
  （表的 VALUE 列即应变率，写入 `condition_json`）；
- 单位制由导入者声明（该文件为 t-mm-s）。

导入是幂等的：同名卡重复导入生成新修订而非重复条目。

## 4. 权限

材料库**写操作仅限管理员**，复用现有 `principal_is_admin()` 判定
（`backend/app/auth/session.py`），不新建角色体系。读对所有登录用户开放。

错误的材料数据会污染其后所有引用它的计算，这是写权限收紧的理由；
将来别名固化（二期）同样仅限管理员。

---

## 5. 前端

- `/sim/materials` 材料库管理页（全局资产，与质量卡模板库同级）：
  材料列表（分类/牌号筛选）、详情页（性能参数表、**曲线预览图**——画出来而非
  只存数、求解器卡原文预览）、导入入口与编辑（管理员可见）；
- 项目侧一期只读：选材料、看曲线。

## 6. 二期规划：零件→材料匹配

> 仅规划，不在一期实现。

场景：从产品数据（dbit BOM 携带材料字段）或 deck 解析拿到"零件 + 原始材料文本"
列表，匹配到库内物理材料。

匹配流水线分四级：精确别名命中 → 规则归一（去空格、大小写、牌号正则）→
AI 模糊匹配（候选 + 置信度，人工确认）→ 未命中进待办。人工确认一次即固化进
`sim_material_alias`，同一写法后续项目自动命中。这与需求条目的
`extracted_by = rule/ai/manual` + `status = draft/confirmed` 是同一模式。

零件清单的主通道一期倾向 deck 解析（自主可控），dbit BOM 通道随对 dbit
契约（架构文档 §6）一并接入。
